# 国际化（i18n）现状与约定

本项目支持 **简体中文 / 英文** 两种界面语言。本文记录机制、覆盖边界、以及「哪些地方**不**本地化」的理由，避免后来者把不该翻译的东西翻译掉。

## 1. 机制

### 应用内文案：`L10n.tr(zh, en)`

```swift
Text(L10n.tr("辅助功能", "Accessibility"))
```

- 不依赖 `.lproj` / `.strings`（SwiftPM 可执行目标对 `.lproj` 支持有限）。
- `L10n.isChinese` **每次调用求值**，不是启动快照 —— 这是「切语言后下一次 body 求值即生效」的前提。
- 语言来源：`L10n.currentLanguage`，由 `AppSettings.language` 驱动（跟随系统 / 强制中文 / 强制英文）。

### 系统级文案：`.lproj`

以下由 **系统** 渲染，`tr()` 管不到，必须走 bundle 资源（`scripts/build_app.sh` 生成）：

| 场景 | 文件 |
|---|---|
| 首次授权时的系统权限弹窗（`NSInputMonitoringUsageDescription`） | `Contents/Resources/{en,zh-Hans}.lproj/InfoPlist.strings` |
| Finder「显示简介」里的名称/版本 | 同上 |

主 `Info.plist` 用英文兜底（`CFBundleDevelopmentRegion = en`），并声明 `CFBundleLocalizations = [en, zh-Hans]`。

### 热切换的传播路径

```
设置页改 language
  → AppSettings.language（@Published）
      ├─ didSet → L10n.currentLanguage（+ 发 .l10nLanguageDidChange、revision += 1）
      ├─ objectWillChange → 设置窗口整棵树重算（tr() 自然拿到新文案）
      ├─ 通知 → AppDelegate.rebuildStatusMenu()（NSMenuItem.title 不走 SwiftUI）
      │         AppDelegate.refreshReadyStatus()（状态行语义状态重新求值）
      └─ 通知 → ReportWindowController 刷新面板标题
                LanguageRefresh 包裹的独立 hosting 根重算 body（引导窗 / 报告窗内容）
```

**启动路径必须单独同步**：`AppDelegate.init` 里 `appSettings = AppSettings.load()` 之后要显式写一次 `L10n.currentLanguage` —— 类 `init` 内对 `@Published` 属性的赋值**不触发 `didSet`**。少了这一行，存了 `.en` 的用户重启后会按系统语言显示，直到碰一次设置项。

## 2. 「不翻译」的部分（有意为之）

### 节点标题是持久化数据，不是文案

画布上的节点名（`"触控板数据"`、`"Force按压识别"`、`"漂移过大?"` …）由 `TimelineMigrator` / `TimelineModuleTemplates` 生成，**存进 config.json**。

**为什么不能给它们套 `tr()`**：全项目有 50+ 处「用标题当 key」的检索，例如

```swift
tl.nodes.first { $0.type == .module && $0.title == "Force按压识别" }   // 判定是否 Force 手势
gesture.updateNodeParams(.compare, title: "压力足够?") { ... }          // 基础设置页写阈值
```

标题一旦随语言变化，Force 手势识别、基础设置页写参数、自定义波形绑定恢复会集体失效。**正确顺序是先给节点加稳定 `role` 标识，再谈标题本地化。**

### 默认配置的手势名/区域名同理

`"左边缘" / "上边缘" / "左侧"` 等是持久化数据，且被 `ConfigStore` 的补齐逻辑按名字判断（`cfg.gestures.contains { $0.name == "上边缘" }`）。改造方案同上：稳定 id + 显示时本地化。

> 已知不一致：`EventConfig` 的默认名走了 `tr()`（`defaultVolume` 等），所以**同一份默认配置里事件名是英文、区域名是中文**。修这个要连同上面两项一起做。

### 日志 / stderr / 诊断文本

- `EngineLog` / `fputs(stderr)` / `print`：面向开发者，保持中文。
- 诊断包（`diagnostics.txt`）与上报消息：收件人是开发者，当前为中文。**但**报告窗口会直接显示 `issue.message`（`ReportView:153`），英文用户会看到中文 —— 这一处仍需处理。

## 3. 守门测试

新增 UI 文案时，以下测试会自动兜住常见错误：

| 测试 | 守住什么 |
|---|---|
| `L10nSourceGuardTests.testEnglishSideOfEveryTranslationHasNoCJK` | 英文参数里混入中文 |
| `…testInterpolationPlaceholdersMatchOnBothSides` | 双语 `\(x)` 数量不一致 |
| `…testNoIdentityTranslations` | `tr("xMin", "xMin")` 这类假翻译虚增覆盖率 |
| `…testMenuTitlesUseTypographicEllipsis` | `...` 与 `…` 混用 |
| `…testScannerFindsExpectedNumberOfTranslations` | 扫描器自身失效（零命中时上面的测试会假绿） |
| `I18nRenderTests.testEnglishLabelsFitTheFixedWidthLabelColumn` | 英文标签超出 150pt 定宽标签列（中文 4 字 ~52pt，永远测不出来） |
| `I18nRenderTests.test*RenderInBothLanguages` | 关键页面在 zh/en 下渲染为空白 |
| `I18nRenderTests.testLanguageRefreshRebuildsBodyOnNotification` | 独立 hosting 根收到通知却不重建 body |

截图产物：`/tmp/touchpad-i18n-shots/{onboarding,basic,event}-{zh,en}.png`

### 写布局的注意点

`Text(L10n.tr(...)).frame(width: 150, alignment: .leading)` 这种「左侧定宽标签列」的布局，**英文侧必须短**。实测上限约 130pt（13pt 系统字体）；`"Collect errors automatically"` = 166.4pt 就会折行并与右侧控件错位 —— 这个是被上面的测试抓出来的，不是肉眼发现的。

## 4. 已知缺口

| 项 | 影响 |
|---|---|
| 节点标题 / 默认手势名 / 默认区域名仍是中文 | 英文界面下面包屑、画布、下拉选项出现中文（需先做 role 改造） |
| 诊断包文本与上报消息为中文 | 报告窗口直接显示 `issue.message`，英文用户可见 |
| 基础设置页的 `Picker` 同时有左侧标签和 Picker 自带标签 | 重复显示一次（如 "Region  Region ⌄"），与语言无关的布局问题 |
| 英文复数用 `issue(s)` / `report(s)` / `gesture(s)` | 英文语境下不专业，需按数量分支 |
