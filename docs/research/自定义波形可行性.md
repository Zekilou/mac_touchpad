# 自定义波形可行性报告

> 日期：2026-10-09 · 机型：Mac17,2 (M5) · 系统：macOS 27.2 (26B5101f) · arch arm64
> 结论：**可行**。已实测跑通「任意参数波形 → 触控板物理震动」的全链路。

## 一、结论速览

| 路线 | 可行性 | 说明 |
|------|--------|------|
| **A. 私有 MTActuator 参数化波形** | ✅ **已实测跑通** | 用字典描述波形，`MTActuationCreateFromDictionary` → `MTActuationActuate`，实测下发成功 |
| B. CoreHaptics（公开 API） | ❌ **Mac 上不可用** | `supportsHaptics = false`，引擎创建报错 `-4809` |
| C. 注册式自定义 ActuationID | ⚠️ 未验证 | `MTActuatorLoadActuations` 存在，但需伪造 HW 产线 plist 并重刷固件槽位，风险高 |

**当前 App 用的是路线 A 的退化形态**：只传 `waveformID`（1~16），波形由 Apple 出厂表决定。
而实际上这套 API **本来就支持传入完整波形定义**——这是我们此前没用到的那一半。

## 二、关键证据

### 证据 1：框架导出了完整的「可编程波形」API

`dyld_info` 提取 `MultitouchSupport` 的导出符号（共 334 个），其中：

```
_MTActuationCreateFromDictionary      ← 从字典创建波形 ★核心
_MTActuationCreateFromParameterizedWaveform
_MTActuationActuate                   ← 播放波形对象 ★核心
_MTActuatorLoadActuations             ← 批量注册（注册式路线）
_MTActuatorGetProductionPlist         ← Apple 自己的波形定义库
_MTActuatorSetWaveform                ← 内部：真正下发字节
```

### 证据 2：Apple 的波形就是「参数字典」

`MTActuatorGetProductionPlist` 返回 134KB XML（已存 `mt_actuations_production.plist`，134,268 字节）：
15 个 actuator 型号 × 8 个波形（ID 1~6, 15, 16），每个都是同构字典：

```xml
<key>BaseWaveform</key>
<dict>
    <key>Type</key><string>Gaussian</string>   <!-- 包络类型 -->
    <key>DurationMS</key><real>6</real>        <!-- 包络时长 -->
    <key>Amplitude</key><integer>19</integer>  <!-- 包络幅度 -->
</dict>
<key>Tones</key>                                <!-- 叠加音，可有多个 -->
<array><dict>
    <key>Type</key><string>Sine</string>        <!-- Sine / Square -->
    <key>FrequencykHz</key><real>1.18</real>
    <key>Amplitude</key><real>0.02</real>
    <key>DurationMS</key><integer>3</integer>
    <key>DelayMS</key><integer>1</integer>
</dict></array>
<key>BaseMultipliers</key>                      <!-- 按按压力度分级 -->
<dict><key>Light</key><real>0.8</real>
      <key>Medium</key><real>1</real>
      <key>Firm</key><real>1.2</real></dict>
<key>ToneMultipliers</key>
<dict><key>Light</key><real>0</real>
      <key>Medium</key><real>0</real>
      <key>Firm</key><real>0.2</real></dict>
```

Apple 原生波形的全部取值空间：

| 字段 | 取值 |
|------|------|
| BaseWaveform.Type | `Gaussian`（全部 8 个） |
| BaseWaveform.DurationMS | `6` |
| BaseWaveform.Amplitude | `0, 19, 22, 35` |
| Tone.Type | `Sine`(8) / `Square`(6) |
| Tone.FrequencykHz | `0.1, 1.18, 1.263, 3.6` |
| Tone.DurationMS | `2, 3, 6` |
| Tone.Amplitude | `0.01 ~ 0.29` |

> 注意：现 App 注释里「1 弱click / 2 强click / 3 buzz / 4-6 tap / 15-16 重击」的直观区分，
> 实际来自 **ToneAmplitude / BaseAmplitude / Frequency 的差异**，而非不同机制。
> 例如 ID 15/16 是纯低频（0.1kHz、无 Gaussian 包络）→ 听感为「嗡」；ID 6 是最大幅度 → 「强重击」。

### 证据 3：自定义字典被接受（不崩、返回有效对象）

`MTActuationCreateFromDictionary(customDict)` 对**任意**字典返回有效 `MTActuation` 对象：

```
### 自定义波形字典 ###
BaseWaveform = { Amplitude = 12; DurationMS = 40; Type = Gaussian; }
Tones = ( { Amplitude = 0.3; DelayMS = 0; DurationMS = 30; FrequencykHz = 0.25; Type = Sine; } )
[result] arg1=NULL -> 0x10273ada0 (接受)
[result] arg1=0x1  -> 0x10273ae60 (接受)
[result] arg1=0x2  -> 0x10273af20 (接受)
```

反汇编也印证了契约——函数入口即校验 `BaseWaveform` 键存在且为字典：

```asm
MTActuationCreateFromDictionary:
    cbz  x0, <return NULL>          ; 字典非空
    bl   CFGetTypeID
    ...
    adrp x1, ...  ; @"BaseWaveform"  ← 强制要求该键
    bl   CFDictionaryGetValue
    cbz  x0, <return NULL>           ; 缺失则返回 NULL
    ...
    b    _MTActuationCreateFromParameterizedWaveform   ; 尾调用真正构造
```

### 证据 4：★ 全链路物理跑通

`MTActuationActuate` 反汇编显示它把字典算成波形缓冲后，用 **waveformID = 83（0x53）** 下发：

```asm
MTActuationActuate:
    bl   MTActuationCalculateWaveform     ; 字典 → 采样缓冲
    cmp  w0, #0x1
    b.lt <返回错误>
    mov  w1, #0x53                        ; ← waveformID = 83，宿主自定义槽位
    bl   MTActuatorSetWaveform(actuator, 83, buffer, count)
```

LLDB 断点实测三次调用（原生 ID 2 参照 → 自定义波形 ×2），全部命中且全部走 83：

```
frame #0: MTActuatorSetWaveform
frame #1: MTActuationActuate + 160
frame #2: MTActuatorActuate  + 180
x1 = 0x53   (waveformID = 83 自定义槽)
x2 = 0x...e900  (波形缓冲指针)
x3 = 0x12   (18 字节采样数据)
```

> 这是关键：**自定义波形走的是 ID 83 专用通道，与原生 1~16 互不干扰**，
> 不会污染 Apple 出厂波形表，也不会改变「系统点击」等其他触觉行为。

### 证据 5：参数化是「真」的（单变量扫描）

每次只改一个参数，下发缓冲对应字节精确变化：

| # | 改动 | 下发缓冲（前 8 字节） | 变化字节 |
|---|------|----------------------|----------|
| 1 | 基线 (dur6 / amp19 / 1.18kHz / 0.02) | `01 13 90 01 00 00 48 13` | — |
| 2 | baseAmp `19 → 35` | `01 23 90 01 00 00 48 13` | byte1 `13→23`，正好 `19→35`(0x13→0x23) |
| 3 | freq `1.18 → 3.6` | `01 13 90 01 00 00 48 06` | byte7 `13→06` |
| 4 | toneDur `3 → 20` | `01 13 90 01 00 00 ff 13` | byte6 `48→ff`（截断饱和） |
| 5 | baseDur `6 → 40` | `01 13 ff 01 00 00 48 13` | byte2 `90→ff`（截断饱和） |

另一组（同一基线，改 toneAmp / Type）：

| 改动 | 下发缓冲 | 变化 |
|------|----------|------|
| 基线 | `01 14 ff 01 00 00 ff ff` | — |
| toneAmp `0.02→0.30`、freq `1.18→0.1` | `01 14 c0 01 00 00 ff ff` | byte2 变化 |
| Type `Sine→Square` | `01 08 ff 02 00 00 ff 06` | byte3 `01→02` |

结论：**Amplitude / Frequency / Duration / Type 四个旋钮真实生效**，且存在饱和截断（超范围会 clamp 到 `0xff`）。

## 三、能力边界

### 能做的

- 自定义**包络**（Gaussian，时长 / 幅度）
- 自定义**音调**（Sine / Square，频率 / 时长 / 延迟 / 幅度，可多个叠加）
- 自定义**按压力度分级**（Light / Medium / Firm 三档倍数）
- 运行时可随时构造新波形，无需重启、无需注册

### 不能做的 / 注意事项

1. **采样数据是内部分编码**，不是浮点 PCM。可见的 8~18 字节是压缩描述，**不能直接喂任意 PCM 音频**。
   → 能做到的是「包络 + 音调合成」，不是「播放任意音效」。
2. `DurationMS` 与 `Tone.DurationMS` 存在**饱和截断**（超限 clamp 到 `0xff`），长音有上限。
3. 马达物理带宽有限：极低频（如 0.05kHz）实际表现取决于硬件，**必须真机试听**。
4. `MTActuatorActuate` 的**第三个参数语义未知**（mactic 与 Apple 内部均传 NULL），当前按 NULL 调用可用。
5. 私有 API，**macOS 更新可能变更**——与现有 MT 触摸通路同一风险等级。

## 四、落地建议

### 阶段 1：桥接层扩展（低风险，直接可用）

在 `mt_bridge` 增加一个入口，把「波形描述」翻译成字典并播放：

```c
typedef struct {
    int   base_duration_ms;    /* BaseWaveform.DurationMS */
    float base_amplitude;      /* BaseWaveform.Amplitude  */
    int   tone_type;           /* 0 = Sine, 1 = Square    */
    float tone_freq_khz;
    float tone_amplitude;
    int   tone_duration_ms;
    int   tone_delay_ms;
} mt_waveform_t;

int mt_actuate_custom(uint64_t deviceID, const mt_waveform_t *wave);
```

- 保留现有 `mt_actuate(deviceID, waveformID)` 不动，作为「预设波形」继续用。
- 新增通路只走 ID 83 自定义槽，**与现有 1~16 预设完全并存**。

### 阶段 2：UI 接入

现有 UI 只暴露了 `waveform` 一个 Int32 字段（`NodeParamsEditorView` 的 waveformCatalog、`BasicGestureSettingsView` 的 Stepper）。
建议二选一：

- **方案 A（推荐）**：保持「预设 1~16」不变，另加一个「自定义波形」开关 + 4 个旋钮（包络幅度 / 音调频率 / 音调时长 / 音调类型）。改动小，向后兼容。
- **方案 B**：把 waveform 字段升级为「预设 ID 或自定义参数」的联合体，需要动 `NodeParams` 的 Codable 与迁移链。

考虑到项目已有复杂的 v1→v10 迁移负担，**方案 A 明显更稳**。

### 阶段 3：真机调参

马达响应无法纸上推导，建议加一个「试听」按钮 + 参数面板，边调边听；
把满意的组合存成用户预设（复用现有 `HapticEvent` 结构，加一个可选 `custom: CustomWaveform?` 字段，`nil` 即走预设）。

## 五、当前代码中值得注意的一处约束

`mt_bridge.c` 现有守卫会**挡住 ID 83**：

```c
if (waveformID < 1 || waveformID > 64) return -1;   /* 83 会被拒 */
```

若后续实现自定义通路，注意这是**新入口**而非放宽现有守卫——现有 `mt_actuate` 的 1~64 语义应保持原样，避免预设路径行为变化。

## 七、风险声明

- 使用 Apple 私有框架 `MultitouchSupport.framework`，与项目现有触摸通路同源同风险，macOS 更新可能失效。
- 尚未验证：马达在不同机型上的实际音色表现、长音饱和上限的精确阈值、连续快速触发时的合并/丢帧行为。
- 建议先在独立探针里完成真机手感调参，确认满意后再接入主 App。
